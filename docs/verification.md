# Проверка ScooterFlow

Дата: 22 октября 2026. Проверки выполнялись на macOS arm64, Go 1.26.1,
Docker/OrbStack, отдельном k3s `scooterflow-k3s` v1.35.2-k3s1.

| Проверка | Результат |
|---|---|
| Buf format/lint/build/generate | Все владельцы и gateway, включая внешних клиентов; закреплённый Docker toolchain |
| PostgreSQL-миграции и xo | Четыре отдельные codegen БД; фактическая генерация not-for-prod/xo v0.0.1 |
| `make test vet` | Пройдено отдельно в каждом из шести Go-модулей; race включён |
| Lifecycle | Сохранённые HTTP/gRPC/reflection/probes/shutdown-тесты Profile и Scooter; runtime tests шлюза |
| `scooterctl up` | Развёрнуты пять приложений, четыре PostgreSQL, Kafka, AKHQ, etcd; readiness достигнута |
| Полный HTTP цикл | RESERVED → ACTIVE → COMPLETED; цена/аванс/возврат проверены через настоящий Kafka/inbox |
| Конкуренция | Два пользователя/один самокат и один пользователь/два самоката: ровно один победитель |
| Идемпотентность | Replay reserve/start/finish без нового состояния; другой состав ключа получает 409 |
| Profile CAS | Подписка обновляется; устаревшая версия не перезаписывает профиль |
| Доступность самоката | Явный is_active=false проходит через шлюз; отсутствующий флаг отклоняется |
| Тарифный снимок | Изменение подписки после reserved не изменяет цену текущей поездки |
| Pricing recovery | При остановке Pricing аренда проходит все шаги; после запуска итог рассчитан |
| Kafka redelivery | Три outbox-события доставлены повторно с прежними correlation ID: inbox остался из 3 строк, цена не изменилась |
| Реальный rollback | Ошибка после вставки аренды и outbox откатила обе записи в PostgreSQL |
| Реальный CAS | Обновление устаревшей версии аренды отклонено |

Unit-тесты отдельно проверяют доступность самоката, название юрлица, недопустимые переходы и время,
неизменность состояния при отказе, округление начатых минут, переполнение денег,
пропуск предшествующего события, повтор аванса и отсутствие fallback тарифа.
Они не подменяют перечисленные проверки настоящих PostgreSQL/Kafka/k3s.

Локальные логи прогонов хранятся в `.local/verification` и не входят в Git.
Проверки не претендуют на нагрузочный benchmark, HA или exactly-once.

## Миграции по таблицам

Начальные миграции разделены: users/subscriptions в Profile и tariffs/trips
в Pricing создаются независимыми файлами с собственными Up/Down. Все миграции
создания названы create_<table>, отдельная миграция индексов — add_inbox_indexes.

На временных БД всех четырёх владельцев проверены Goose up-by-one и down для
каждого файла, повторный up и seed. После полного up колонки и индексы совпали
с прежней схемой. Временные БД удалены. Тесты scooterctl на сборку migration Job

В существующем локальном стенде subscriptions и trips уже были созданы старой
начальной миграцией. После сверки схемы их отдельные версии отмечены в истории
Goose однократно; данные Profile и Pricing до/после совпали. Для нового клона
никаких переходных действий не требуется. Повторный scooterctl deploy прошёл,
все компоненты готовы. Результаты: .local/verification/table-migrations.json
и table-migrations-deploy.log.

## Application services и точечные изменения

После рефакторинга выполнен `make test vet` для всех шести модулей (race включён).
Проверены частичные обновления Profile/Scooter, сохранение исходного снимка при
ошибке поля или storage, единственная новая версия для нескольких изменённых
полей, транзакционный context Profile и Rental. Доменные события Rental проверены
на неизменность снимков нескольких переходов до flush и сохранение correlation ID
при повторном flush. Повторные/запрещённые переходы не добавляют события.

Все четыре владельца пересобраны и развёрнуты в k3s. Через HTTP прошли 11 групп
проверок: изменения нескольких полей и отсутствие частичной записи, пропущенные
поля и явный ноль, версии, бронь/start/finish/cancel, тарифный снимок, аванс/итог,
конкурентные запросы и восстановление Pricing после остановки. Использовались
отдельные временные пользователи и самокаты; после проверки удалены только их
записи и события. Остальные данные не сбрасывались.

Подтверждены единый формат hotel.yaml/scooter.yaml, отсутствие model.go и
экспортоподобных локальных переменных, исключение агентских файлов из индекса
Git с сохранением локальных копий. Последний deploy оставил все 12 компонентов
готовыми. Логи: .local/verification/application-services-*.log.


## Input use case, атомарная проверка версии и раздельные записи Profile

После уточнения границ слоёв `go test -race ./...` и `go vet ./...` прошли в
Profile, Scooter, Rental и Pricing. Для новых тестов start/finish/cancel отдельно
выполнен `go test -race ./internal/application/...` в Rental. Проверены переходы,
повторы, неверный владелец, запрещённое состояние, ошибки Save/Flush и единый
транзакционный context состояния и событий. Use case передаёт application service
уже изменённую сущность; Input каждого сценария объявлен собственным struct.
Сквозные Changes/Reservation/Event DTO application services удалены.

CheckVersion удалён из Profile и Scooter. На реальном PostgreSQL прошли 14
сценариев: устаревший expected_version при свежем снимке, изменение БД после
чтения, ожидаемая версия впереди прочитанного снимка, пустой PATCH с неверной
версией, сохранение версии/времени при пустом PATCH и ровно один победитель двух
конкурентных записей. Дополнительно Profile: Save не пишет subscriptions;
SaveSubscriptions не пишет users; ошибка второй записи в application service
откатывает первую, включая версию. Проверки запускались на отдельных UUID,
которые удалены через cleanup. Локальные SQL-пробы:
services/{profile,scooter}/.local/verification/cas/postgres_test.go;
команда в модуле: `go test -race -count=1 -v ./.local/verification/cas`.

Четыре образа пересобраны и развёрнуты. Итоговый HTTP-прогон прошёл все 11 групп:
частичные PATCH, устаревшие/будущие версии и пустой PATCH, полный цикл аренды,
повторные запросы, тарифный снимок, конкурентное бронирование и восстановление
Pricing через Kafka/inbox после остановки. Первые прогоны прерывались сетевым
таймаутом после смены pod; диагностический polling восстановления исправлен,
чтобы временный timeout оставался внутри его 45-секундного окна. В runtime
retry/timeout политики не менялись. Временные записи и события удалены,
существующие данные сохранены.

Результаты: .local/verification/boundaries-*-tests.log,

## Две операции обновления Scooter и упрощение Pricing

Scooter обновляет is_active и owner отдельными ручками. Заряд удалён из proto,
сущности, SQL, seed и проверки Rental. Название юрлица хранится строкой, обрезаются
краевые пробелы; допустимо от 1 до 200 символов. Общий PATCH самоката удалён.
Pricing вызывает storage из use case и изменяет загруженный Trip напрямую,
без однострочных application services и копирования сущности.

В Scooter, Rental, Pricing и api-gateway прошли `go test -race ./...` и
`go vet ./...`. Buf format/lint/build/generate выполнены для Scooter, Rental
и gateway. После удаления reserved повторены генерация и test/race/vet в трёх
затронутых модулях. XO действительно сгенерирован из изолированной PostgreSQL 16;
Goose up/down/up и seed пройдены. Bootstrap-миграция создаёт scooters с is_active
и owner. В действующей учебной БД схема обновлена с сохранением четырёх самокатов,
номеров, марок и счётчиков наезда; прежние записи сохранены в локальный JSON.

HTTP-проверка на отдельных временных UUID прошла семь групп:

1. Чтение карточки/списка возвращает is_active и owner без заряда.
2. Две независимые операции корректно передают false и Unicode-название,
   сохраняют остальные поля самоката.
3. Отсутствующий/null флаг, пустое/слишком длинное название и неположительная
   версия дают 422; удалённый общий PATCH — 405. Запись остаётся прежней.
4. Устаревшая и будущая версии дают 409, в том числе при прежнем значении поля;
   прежнее значение с актуальной версией сохраняет version и updated_at.
5. Конкурентные обновления разных полей с одной версией имеют ровно одного
   победителя; второе отклоняет SQL CAS.
6. Неактивный самокат нельзя забронировать; включение разрешает бронь.
   Отключение после брони не мешает повтору, start и finish. Pricing через Kafka
   рассчитывает итог, а новая бронь отключённого самоката отклоняется.
7. Реальная SQL-схема содержит is_active/owner и не содержит charge_percent.

Временные данные и события удалены проверкой, остальные данные сохранены.
Логи: `.local/verification/two-updates-{proto-*,build,deploy,schema,http}.log`,
`two-updates-http.json`, `two-updates-*-tests.log`, `no-reserved-*-tests.log`.
